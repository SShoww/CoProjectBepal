# Rules — workflow, ขอบเขต, เกณฑ์จบ

กติกาการสื่อสารและการแก้ไขทั่วไปอยู่ใน [AGENTS.md](../AGENTS.md) ไฟล์นี้เป็นเจ้าของหลักของ workflow
การจัด Context ไม่เปลี่ยนนโยบาย build/test/deploy ของแอป (ดู [CLAUDE.md](../CLAUDE.md))

## Workflow ต่องาน
1. อ่านตามลำดับใน [README.md](../README.md)
2. ตรวจ Board ว่ามี Quest ที่ Files ทับกับงานนี้หรือไม่ ([Agent-Handoff.md](Agent-Handoff.md))
3. งานที่แก้ไฟล์และไม่ใช่งานเล็กครั้งเดียว: สร้าง Quest ก่อนแก้ไฟล์อื่น (งานถาม-ตอบ/แก้ 1 บรรทัดตามคำสั่งตรงไม่ต้องมี Quest)
4. แก้เฉพาะไฟล์ใน Files ของ Quest ตัวเอง — scope เปลี่ยน ติด blocker หรือหยุดงาน → อัปเดต Quest ทันที
5. จบงานตาม [เกณฑ์จบ](#เกณฑ์จบ)

## ขอบเขต
- Quest ระบุ Files เป็น path ชัดเจน (glob ระดับโฟลเดอร์ได้ เช่น `Context/**`) ห้ามใช้ "all"
- ไม่เดาสถานะงานเก่า ถ้าไม่ชัดให้คง `waiting` และถามผู้ใช้
- ข้อมูลไม่ชัดหรือขัดกัน: ถามผู้ใช้ และทำส่วนที่ไม่ติดคำถามต่อ

## หลาย agent
- เริ่ม agent เพิ่มเมื่อผู้ใช้สั่งเท่านั้น
- แต่ละ Quest มีเจ้าของ (Owner) ชัดเจนหนึ่งราย
- ก่อนแก้ไฟล์ ตรวจ Files ของ Quest ที่เปิดอยู่ทั้งหมด — ถ้าทับกัน ให้ตกลงเจ้าของส่วนที่ทับผ่านผู้ใช้ก่อนแก้
- ไม่แก้ ปิด หรือยึด Quest ของ agent อื่นเอง เปลี่ยน Owner เมื่อได้รับคำสั่งให้รับช่วงเท่านั้น
- ก่อนอัปเดต Quest อ่านไฟล์ล่าสุด แล้ว patch เฉพาะส่วนของตัวเอง ไม่เขียนทับจาก snapshot เก่า
- ไม่มีไฟล์ Board รวม — Board คือโฟลเดอร์ `quests/` (หนึ่งไฟล์ต่องาน) เพื่อไม่ให้ agent เขียนทับกัน
- ห้ามถือว่างานถูกทิ้งเพราะเวลาผ่านไป
- ไฟล์ที่มีการแก้ค้าง (uncommitted) และไม่มี Quest เจ้าของ ให้ถือว่าเป็นงานของคนอื่น ไม่แตะ

## เกณฑ์จบ
1. ตรวจให้ตรงชนิดการเปลี่ยนแปลง (เอกสาร → ลิงก์/ความสอดคล้อง, โค้ดเกม → build + `--autoplay`/`--shots` ตาม [CLAUDE.md](../CLAUDE.md), script → รันทดสอบ)
2. บันทึกผลตรวจ ข้อจำกัด และ next action ใน Quest
3. ถ้าแก้ไฟล์ เขียน Edit Log หนึ่งรายการ ([Edit Log](#edit-log))
4. ผ่านครบ → ตั้ง `ready-to-close` และเสนอปิดด้วย Quest ID; ยังไม่ครบ → `waiting`/`blocked` พร้อมสิ่งที่ขาด
5. รอผู้ใช้ยืนยันก่อนย้าย Quest ไป `archive/quests/` (ถ้าผู้ใช้สั่งปิดไว้แล้ว ปิดได้เมื่อผ่านครบ)
6. ปิดเฉพาะ Quest ที่ได้รับคำสั่ง ไม่เหมารวมทั้ง Board
7. ก่อนย้ายไฟล์ ตรวจ resolved source/target ว่าอยู่ใน `Context/quests/` → `Context/archive/quests/` จริง

## Edit Log
```sh
python tools/context/log-edit.py --quest Q-ID --files "path/a, path/b" --summary "แก้อะไรและเพราะอะไร" --validation "ผลตรวจและข้อจำกัด"
```
- บันทึกหนึ่งรายการเมื่อจบหรือหยุดส่งต่องาน ไม่บันทึกทุกครั้งที่เซฟ
- [Edit-Log.md](Edit-Log.md) เก็บล่าสุด 10 งาน งานละ 3 บรรทัด รายการเก่าย้ายไป `archive/edit-log/YYYY-MM.md` อัตโนมัติ
- Quest ID ซ้ำ → อัปเดตรายการเดิม (ขึ้นบนสุด)
- ใช้ lock + atomic write; ติด lock จะรอแล้วลองใหม่ ไม่ลบ lock ของ agent อื่น (lock ค้างเกิน timeout → script หยุดพร้อม error ให้ผู้ใช้ตัดสิน)
- ห้ามใส่ secrets หรือข้อมูลส่วนตัว (script ปฏิเสธข้อความที่ดูเหมือน token/password)
